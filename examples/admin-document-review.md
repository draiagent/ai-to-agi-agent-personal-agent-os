# 行政文件整理：模擬案例

以下檔名、資料與決策均為虛構教學輸入；不是實際企業驗證或 ISO 合規結論。

## 任務

在指定日期前整理教育訓練文件，產出索引與缺件表。允許讀取指定資料夾與需求信件、建立整理副本；禁止刪除原檔、寄出報告或自行認定生效版本。

## 模擬輸入

| 檔案 | 內容 |
|---|---|
| request.txt | 需求為提供 A、B、C 三份訓練紀錄 |
| training-A.pdf | 已有 A 紀錄 |
| training-B.pdf | 已有 B 紀錄 |
| SOP-v1.pdf | 舊格式，效力未明 |
| SOP-v2.pdf | 新格式，效力未明 |

## 操作與分工

1. Astra 定義驗收：三筆需求逐一對應到檔案或缺件狀態；所有版本疑義保留。
2. dot 透過已授權工具取得需求與期限。本例使用上述靜態輸入模擬。
3. Codex 整理檔案索引，發現缺 C 紀錄、SOP 版本衝突。
4. Check：確認 C 未出現在本次提供資料；只標「本次資料未提供」，不斷言企業從未完成訓練。
5. Correct：查核受控文件清單；仍無清單時保留 Pending，交由負責人確認。
6. 模擬負責人回覆「v2 為現行版本」，將回覆本身作為本例的新增證據；不假稱真實人員已核准。
7. Verify：比對三項需求及兩項疑義，確認全部有可追溯狀態。
8. Remember：保存已驗證索引；C 的缺件待補狀態仍為 Pending，不標成完成。

## 預期成果

| 需求或疑義 | 結果 | 依據 |
|---|---|---|
| A 紀錄 | 已提供 | training-A.pdf |
| B 紀錄 | 已提供 | training-B.pdf |
| C 紀錄 | 本次資料未提供，待補 | 輸入清單及逐項比對 |
| SOP 版本 | 模擬確認 v2 | 案例設定的負責人回覆 |

本次「整理與列出缺件」可以完成；「補齊全部訓練紀錄」尚未完成。實作時須存實際來源位置、確認日期、負責人決定及驗收紀錄。

## 練習與評量

拿掉模擬負責人回覆，重新判定 SOP 狀態。通過條件：保留 Pending、不猜生效版本、列出所需補件，並區分整理完成與資料齊全。另記人工與工具成本，不填入未測量的效率數字。
